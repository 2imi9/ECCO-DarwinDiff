## Headline finding (notebook 4)

The differentiable scaffold is methodologically sound for joint multi-parameter learning, but **identifiability is per-parameter and per-observation-type**.

Concretely, when four parameters (μ, m_lin, m_quad, r_remin) of a closed-loop NPZ system are recovered jointly:

| Parameter | Steady-state RMSE | Trajectory RMSE | Improvement |
|---|---|---|---|
| μ | 79 % | 11 % | 7× |
| m_lin | 46 % | 22 % | 2× |
| m_quad | 47 % | 42 % | 1.1× |
| r_remin | 308 % | 88 % | 3.5× |

Reading: time-resolved observations (5 snapshots through the integration) dramatically improve μ recovery, moderately improve m_lin and r_remin, and barely improve m_quad. r_remin retains a residual partial degeneracy with the mortality terms because it enters the equations multiplicatively. Even time-resolved data does not fully break this. Pinning down r_remin would require a different observation type entirely (POC export flux, total mass), not better statistics on N and P.

Implication for real Darwin: BGC-Argo time series will identify rate parameters that ship-cruise snapshots cannot; some parameter pairs will need additional observation types regardless of time resolution. The practical task is figuring out, per parameter, which observation set actually constrains it.

## Parameter inventory recap

- **Darwin 1** (`v04/llc270_JAMES_paper`, Carroll 2020 build): 103 independent tunable scalars in `darwin_init_fixed.F`. Carroll 2020 calibrated **6** via Green's functions = **5.8 % calibration coverage**. The other 94 % are held at expert / literature defaults; one of them (the 100-day fixed DOC remineralisation rate) is explicitly flagged by Savelli et al. 2026 as a real limitation.
- **Darwin 3** (`v06/llc270` build): 100 distinct tunable parameter names exposed via namelist, 657 individual values when arrays are expanded over plankton, group, and matrix dimensions. Architectural difference that matters: Darwin 3 is namelist-driven, so spatially-varying parameter learning does not require source recompiles. Significantly cheaper integration target if v06 is acceptable.

Full per-namelist breakdown with every parameter name listed: `docs/ecco_darwin_parameter_inventory.md`.
